# Algorithm Mapping and Complexity Guide

This document maps the implemented Java 17 code to the DSA2 topics in the authoritative `25SC1305E` syllabus and to the DSA3 plagiarism-analysis requirements. It describes the code that exists in this repository; it does not claim that a library-only implementation is used by the console when it is not.

All core structures and algorithms use primitive arrays, generic arrays, or custom nodes. They do not delegate to Java collection implementations, `Arrays.sort`, `Collections.sort`, streams, or an external algorithm library.

## Reading the map

Implementation status has the following meaning:

- **Application**: reached by a console option or report export.
- **Support**: used inside another application component.
- **API/test**: complete public implementation with invariant or algorithm tests, but not currently called by a console workflow.

Complexities exclude caller-owned input storage unless stated otherwise. Output space is identified where it materially changes the bound. “Average” hashing assumes a well-distributed `hashCode`; average BST cost assumes non-adversarial insertion order. A comparison is treated as `O(1)` in the tables; comparing long strings adds the cost of the compared prefix. Where a deterministic algorithm has one time bound rather than separate average/worst columns, that bound applies to both unless a caveat says otherwise.

Notation:

- `n`: number of stored items; `h`: tree/trie height.
- `C`: input characters; Java character algorithms count UTF-16 code units; `T`: token count.
- `m`, `n`: the two sequence lengths in a two-input algorithm.
- `w`: shingle width; `a`, `b`: the two shingle-array lengths; `s_w`: stopword count; `w_s`: compared stopword/token length.
- `P`: total characters across patterns; `q`: pattern count; `z`: emitted matches; `beta`: maximum trie-node branching.
- `k`: MinHash signature length; the batch engine fixes `k = 128`.
- `S`, `R`: submission and reference counts; `Q`: shortlisted pairs.
- `V`, `E`: graph vertices and logical edges.
- `A`: evidence/set candidates; `K`: maximum selected items; `U`: universe size; `L`: total candidate-to-universe incidences.
- `t`: B-tree minimum degree; `o`: B+ tree order; `r`: counting-sort numeric range.
- `sigma`: distinct byte values (`<= 256`); `B`: encoded Huffman payload bits.
- `alpha(n)`: inverse Ackermann function, effectively constant at project sizes.

## Weighted graphs and graph algorithms

`algorithms.graph.WeightedGraph<V>` stores labels in a resizable array and custom linked adjacency nodes. It uses `O(V+E)` space; an undirected logical edge has two adjacency nodes except a self-loop. Vertex indexes remain stable. Label lookup is linear, so `addVertex` is `O(V)` because it rejects duplicate labels, and label-based edge insertion adds two `O(V)` lookups. Index-based edge insertion/update searches the source adjacency list in `O(degree)`.

| Algorithm and concrete class/method | Observable feature and why selected | Time | Auxiliary space | Bounds and caveats |
|---|---|---|---|---|
| Breadth-first search — `WeightedGraph.breadthFirst` | **Application.** After a menu 8 start ID is entered, the console prints level-style reachability using `LinkedQueue`, with no library queue. | `O(V+E)` | `O(V)` | Traverses one reachable component from the selected vertex. |
| Depth-first search — `WeightedGraph.depthFirst` | **Application.** Menu 8 also prints an alternative exploration order using iterative `LinkedStack`. | `O(V+E)` | `O(V)` | Neighbor order reflects head-inserted adjacency order, but remains deterministic for a fixed build order. |
| Connected components — `WeightedGraph.unionFindComponents` | **Application.** Menu 8 uses the reusable `DisjointSet` to show thresholded multi-document similarity groups. The BFS implementation remains available for traversal/cross-checking. | `O(V+E alpha(V))` | `O(V)` plus returned member arrays | Every loaded document is inserted as a graph vertex. Isolated documents are deliberately omitted only from the displayed multi-document groups. |
| Kruskal minimum spanning forest — `MinimumSpanningTree.kruskal` | **Application.** Menu 8 displays compact relationship links. Similarity is converted to cost `max(10^-6, 1-similarity)`, so low-cost selected links represent stronger matches. | `O(E log E)` | `O(V+E)` | Uses manual merge sort and the reusable path-compressed `DisjointSet`. A disconnected graph returns a forest and component count, not a fabricated spanning tree. |
| Prim minimum spanning forest — `MinimumSpanningTree.prim` | **API/test.** Alternative MST implementation for syllabus comparison without a priority queue. | `O(V^2+E)` | `O(V)` plus output | Array minimum selection is deliberate and can beat heap overhead only on small/dense graphs. Not called by the console. |
| Dijkstra — `ShortestPaths.dijkstra` | **Application.** Menu 8 reconstructs a relationship path by minimizing the sum of `1-similarity` edge costs with the custom minimum heap. | `O((V+E) log E)` | `O(V+E)` worst with stale heap entries | Rejects any negative edge. The displayed “strongest path” is minimum additive dissimilarity; it is not a maximum-product or maximum-bottleneck path and does not establish copying direction. |
| Bellman–Ford — `ShortestPaths.bellmanFord` | **API/test.** Alternative for directed graphs with negative weights; marks every vertex reachable from a reachable negative cycle as negatively unbounded. | `O(VE)` | `O(V+E)` | A path affected by a negative cycle is deliberately not reconstructed. Console costs are non-negative, so Dijkstra is used instead. |
| Floyd–Warshall — `ShortestPaths.floydWarshall` | **API/test.** All-pairs distances and path reconstruction, including affected-pair negative-cycle marking. | `O(V^3)` | `O(V^2)` | Quadratic matrices make it suitable only for smaller graphs; not used in the console path query. |
| Kahn topological sort — `DirectedGraphAlgorithms.topologicalSort` | **API/test.** Produces a DAG order or maximal acyclic prefix using an array queue. | `O(V+E)` | `O(V)` | Requires a meaningful directed relation. `blockedVertices` can include vertices downstream from a cycle, not only cycle members. The current similarity graph is undirected and does not infer source/copy direction, so the console does not fabricate a topological claim. |
| Kosaraju strongly connected components — `DirectedGraphAlgorithms.stronglyConnectedComponents` | **API/test.** Finds cycles/groups in a directed graph using iterative first-pass DFS and a custom transpose. | `O(V+E)` | `O(V+E)` | Fully implemented and tested for future directed provenance data; the current undirected similarity model has no defensible causal edge direction. |

`analytics.SimilarityNetwork` also stores a `double[V][V]` similarity matrix, so its actual memory is `O(V^2)` even though `WeightedGraph` itself is sparse. Its graph is bipartite-like submission-to-reference evidence made undirected; groups and paths show association, not authorship, chronology, intent, or proof that one student copied another.

## Greedy approximation, flow, and compression

| Algorithm and concrete class | Observable feature and why selected | Time | Space | Guarantees and limits |
|---|---|---|---|---|
| Greedy evidence selection — `GreedyEvidenceSelector` | **Application.** `DocumentAnalyzer` caps a case report at `settings.maxEvidence`, choosing high-relevance evidence with new type/item coverage per excerpt cost. | `O(KL + U)` for at most `K` picks; worst `O(KAU)` for `A` dense candidates | `O(A+U+K)` | Deterministic ties. Relevance weighting and a hard item cap make this a practical heuristic, not a formal set-cover approximation guarantee. Each evidence item has a private universe element, so positive candidates can continue filling the cap. |
| Weighted greedy set cover — `SetCoverSolver` | **API/test.** Adapts sets to the selector with relevance 1 and reports uncovered universe elements. | `O(AL + U)` with at most `A` picks; dense worst `O(A^2U)` | `O(A+U)` plus adapted incidence copies | For positive costs this is the standard cost-aware greedy rule with a harmonic approximation bound when full coverage is feasible. Universe elements must be integer indexes `0..U-1`. Not used by the current console. |
| Edmonds–Karp maximum flow — `EdmondsKarpMaxFlow` | **Application.** `ReviewerAssignmentService` constructs source→case→reviewer→sink edges; unit case capacity and reviewer capacities maximize the number assigned. | capacity-matrix BFS is `O(V^2)`; at most `O(VE)` augmentations gives actual bound `O(V^3E)`, dense worst `O(V^5)`. The assignment network has at most one augmentation per case, giving the tighter `O(cases * V^2)` bound. | `O(V^2)` capacity, residual, and net-flow matrices | Long capacities and overflow checks. This is maximum cardinality only: it has no min-cost preferences, expertise weights, or fairness objective. The service currently marks every reviewer eligible and relies on prior risk ordering plus deterministic vertex order. |
| Huffman coding — `HuffmanCodec` | **Application.** `ReportWriter` exports every readable report and a self-contained UTF-8 `.huff` version. Greedy frequency merging was selected for prefix-free lossless coding. | `O(n + sigma log sigma + sigma^2 + B)`, where `sigma <= 256` and `B` is payload bits; the `sigma^2` bound covers worst-depth code-string construction. With a fixed byte alphabet this is linear in input/output size. | `O(sigma + compressed + original output)` | Header is `10 + 5*sigma` bytes (magic/version, original length, symbol-frequency pairs). Small or high-entropy reports can expand. Format has validation but no checksum/authentication and is not streaming. Decompression exists in the codec/test API; the console exports but does not provide a `.huff` import command. |

## Text preparation, shingles, and exact matching

| Algorithm and concrete class | Observable feature and why selected | Time | Space | Practical bounds and interpretation |
|---|---|---|---|---|
| Unicode-aware normalization — `TextNormalizer.normalize` | **Support/API.** Lowercases letters/digits from Unicode code points, maps other runs to one space, and gives deterministic comparison text. | `O(C)` | `O(C)` output | Simple lowercase normalization only: no Unicode normalization form, stemming, homoglyph detection, or locale-sensitive expansion. |
| Offset-preserving preparation — `core.TextPreparation` | **Application.** Prepares each document once by Unicode code point and stores normalized→original UTF-16 offsets so menu 6 and reports can show source line/column locations. | `O(C + stopword trie build + token lookup)` | `O(C+T+S)` | Supplementary-plane letters are retained and lower-cased. Locations and character matches still use Java UTF-16 offsets. |
| Tokenization/stopword filtering — `TextNormalizer.tokenize*`, `Trie<V>` | **Application/support.** Supplies word shingles and token DP; `TextPreparation` indexes normalized stopwords in the custom generic trie. | tokenization `O(C)`; trie lookup `O(tokenLength * log beta)` with sorted child arrays | `O(T+C+S)` including token strings and trie nodes | No library set/map is used. Trie edges are UTF-16 units, while whole token strings remain intact. |
| Word/character shingles — `ShingleGenerator`; facade `Shingler` | **Application.** Word shingles measure reordered phrase overlap; character shingles retain evidence under small word-level changes. | word `O((T-w+1)w)`; character `O((C-w+1)w)` because Java substrings copy; generation time equals output character volume | same order as generated output | Empty when shorter than width. Character shingles are UTF-16 windows and can split a surrogate pair. `DocumentAnalyzer` caps each character window at **100,000** code units. |
| Set Jaccard — `ShingleGenerator.jaccardSimilarity` | **API/test.** Exact set similarity without any set structure. | `O(a^2+b^2+ab)` | `O(1)` auxiliary | Duplicates are ignored setwise. The application uses its custom `HashSet` version instead: expected `O(a+b)`, collision worst quadratic, and stores `O(a+b)` unique shingles. |
| Knuth–Morris–Pratt — `KMP` | **Application.** Exact passage search and evidence location; token-array matching is also public. Prefix fallback guarantees linear scanning. | `O(n+m+z)` | `O(m+z)` | Returns UTF-16 positions for strings; overlapping matches supported. |
| Rabin–Karp — `RabinKarp` | **Application.** Round-robin exact phrase search demonstrates rolling hashing while verifying every hash hit to prevent false evidence. | expected `O(n+m)` when verified hash hits are rare; more exactly `O(n+m+H*m)`, where `H` is the number of genuine or colliding hash hits; worst `O(nm)` | `O(z)` | Modulus `1,000,000,007`, base 257. Hash collisions cannot create false matches because characters are verified, but collisions or many genuine overlapping matches can trigger the worst case. |
| Z algorithm — `ZAlgorithm` | **Application.** Third exact-search route and independent linear-time evidence check. | `O(n+m+z)` | `O(n+m+z)` | Builds a combined integer array with a reserved separator, so it allocates more than KMP but has a direct Z-box implementation. |
| Generic trie — `Trie<V>` | **Application/support.** `TextPreparation` uses exact-key lookup for stopword filtering; the public prefix/enumeration API remains reusable and tested. | lookup `O(keyLength * log beta)`; insert/remove worst `O(keyLength * (beta+log beta))` due child shifts; enumeration `O(subtree nodes + output characters)` | `O(total key characters)` plus capacity slack and recursion `O(h)` | Uses UTF-16 `char` edges. Empty key is allowed. Enumeration/counting is recursive, so exceptionally deep keys can exhaust the stack. The Aho implementation owns a separate failure-link trie. |
| Aho–Corasick — `AhoCorasick` | **Application.** Searches up to 512 eligible exact phrases together and reports the first multi-pattern evidence occurrence. | search `O(C*beta + z)` amortized; construction worst `O(P*h*beta + inherited outputs)` with linear child scans/failure walks | `O(P + inherited output references + z)` | Empty patterns rejected; duplicates are retained and emitted. `DocumentAnalyzer` caps the application automaton at **512 patterns**. Child transitions are linear arrays, not constant-time alphabet tables, so the usual textbook `O(C+z)` assumes a factor not present here. The search materializes all matches even though `DocumentAnalyzer` consumes only the first. |

`DocumentAnalyzer` generates exact phrases across the complete submission token stream and searches the reference separately for each phrase before the capped Aho pass. That makes the pair-level exact stage potentially quadratic in document size even though KMP and Z are linear per search. The configurable file-size guard defaults to 2,000,000 bytes, but there is no separate cap on the number of round-robin exact phrase searches.

| Levenshtein edit distance — `EditDistance` | **Application.** Token-level normalized similarity contributes to the fuzzy composite; character overloads are public. | `O(mn)` | `O(min(m,n))` rolling rows | Returns distance/similarity, not an edit script. Unit insertion/deletion/substitution costs only; no transposition. |
| Smith–Waterman local alignment — `FuzzyAlignment`; facade `SmithWaterman` | **Application.** Locates the best local token passage and supplies half-open ranges, raw score, normalized score, and excerpts. | `O(mn)` | `O(n)` rolling score and start-coordinate rows, plus returned slices | It propagates start coordinates but does **not** retain a full gapped traceback/alignment string. `DocumentAnalyzer` bounds each sequence to the **first 900 tokens**, so evidence later in a longer document may be missed. Character overloads operate on UTF-16 code units. |

For one verified pair, the three fuzzy algorithms remain `O(mn)` time. The 900×900 application window bounds each individual DP table scan, but it is a prefix window rather than a sliding search across the full document.

## Randomized shortlisting and deterministic parallel work

| Algorithm and concrete class | Observable feature and why selected | Time | Space | Statistical/operational limits |
|---|---|---|---|---|
| Deterministic MinHash — `MinHash` | **Application.** `BatchAnalyzer` hashes word-shingle sets once, compares 128-component signatures, and avoids expensive full analysis below `candidateThreshold`. | one signature `O(total shingle characters + shingles*k)`; estimate `O(k)`; `D`-document public shortlist `O(D^2*k)` after signatures | one signature `O(k)`; all signatures `O(Dk)` plus candidates | Estimate is the fraction of equal signature coordinates, not exact Jaccard. At true similarity 0.5 and `k=128`, ideal MinHash sampling has about **4.4 percentage points one-standard-error** uncertainty. Deterministic mixed 64-bit hashes are reproducible but are not proofs of independent random permutations; hash collisions and threshold false positives/negatives remain possible. ## Reviewer-flow network details

`ReviewerAssignmentService` first filters by `reviewThreshold` and uses stable `GenericSorts.mergeSort` to place higher composite scores first. It then calls `EdmondsKarpMaxFlow.assignCases` with:

- source→case capacity 1;
- case→eligible-reviewer capacity 1;
- reviewer→sink capacity equal to reviewer workload capacity.

This guarantees that no case is assigned twice and no reviewer exceeds capacity. It maximizes count, not total risk score. Because all reviewers are currently eligible, assignment does not model subject expertise, conflicts of interest, preferred workload, or weighted priority; those would require eligibility data and, for optimization beyond cardinality, min-cost maximum flow.

## Practical bounds and honest limitations

1. **MinHash is an estimate.** The 128-component signature can exclude a genuinely similar pair near the threshold. Reports show exact shingle scores only after a pair is shortlisted; the MinHash estimate is not itself plagiarism evidence.
2. **Shortlisting remains quadratic in corpus counts.** There is no LSH band index; every `S*R` signature pair is inspected.
3. **DP is bounded by prefixes.** Smith–Waterman, LCS length, and edit distance use at most the first 900 tokens from each document. This controls time and memory but can miss later passages.
4. **Rolling DP cannot reconstruct.** LCS length and edit distance use `O(min(m,n))` rows and therefore do not return a sequence/edit script. Full LCS reconstruction intentionally switches to `O(mn)` memory. Smith–Waterman returns ranges without a gapped traceback.
5. **Character semantics are UTF-16.** Exact match offsets, character shingles, tries, Aho–Corasick, and character DP count Java `char` units. Code-point-aware preparation retains supplementary-plane letters and maps both surrogate units back to source offsets, but character shingles can still split a surrogate pair.
6. **The graph proves association only.** It is undirected and has no timestamps or authorship inference. The menu label “copying path” means a low-dissimilarity relationship path, not a causal copying direction. Topological sort and SCC remain implemented/tested APIs until meaningful directed provenance data exists.
7. **Graph memory is quadratic at the application layer.** `SimilarityNetwork` keeps a full similarity matrix; Floyd–Warshall and max flow also use matrices. These implementations target academic/demo corpus sizes, not millions of vertices.
8. **B+ deletion rebuilds.** Lookup, insertion, and range scans are logarithmic/output-sensitive, but each deletion is `O(n log n)`. The persistent catalog serializes ordered B-tree/B+ records rather than raw node pages, so it reloads in `O(n log n)` and revalidates its custom-tree invariants.
9. **Range-wide flag maintenance is not lazy.** `RangeAnalytics.addToRange` touches each affected score to keep Fenwick threshold counts exact.
10. **Counting sort is range-limited.** The default maximum count array is 10,000,000 entries; arbitrary full-domain integer input should use radix, merge, quick, or heap sort.
11. **Huffman is a whole-buffer teaching format.** It may expand small/incompressible reports, has no checksum or streaming mode, and has no console decompression command.
12. **Maximum flow is cardinality-only and matrix-backed.** It enforces eligibility and capacity but not weighted preference or fairness, and its `O(V^2)` matrices limit very large reviewer networks.
13. **Exact phrase work can dominate.** Individual KMP/Z searches are linear, but `DocumentAnalyzer` can run one full reference search per generated submission phrase. Only the Aho pattern set is capped at 512.
14. **Benchmarks are comparative, not scientific JVM benchmarks.** They use `System.nanoTime` in the live process without forks, warm-up isolation, GC control, or statistical confidence intervals.
15. **Alternative algorithms are not fabricated as plagiarism findings.** The live workflow selects Kruskal over Prim and non-negative Dijkstra over Bellman–Ford/Floyd–Warshall. Topological sort and SCC remain API/test-visible because the corpus has no defensible directed provenance relation. `SetCoverSolver` is a general adapter over the same greedy selector used for evidence compaction, not a second application policy.

## Verification surfaces

- `StructureSelfTests` exercises collisions/resizing, heap order, all AVL rotation families and deletion, B-tree/B+ splits and deletion behavior, range structures, and union–find invariants.
- `TextAlgorithmSelfTests` exercises normalization, shingles, exact matchers, trie/Aho–Corasick, LCS, edit distance, fuzzy alignment, and MinHash determinism/candidates.
- `AdvancedAlgorithmSelfTests` exercises traversal/components, both MST algorithms, shortest paths and negative cycles, topological sort/SCC, max flow/min cut and reviewer capacity, greedy cover, Huffman corruption checks, every sort, and benchmark result integrity.
- `BenchmarkService` makes timing, tree-height/invariant, MinHash reduction, and sequential-versus-parallel equality observable through console option 11.

These tests validate implementation invariants and deterministic examples. They do not turn probabilistic MinHash estimates, benchmark timings, similarity scores, or graph associations into a finding of academic misconduct; exported reports explicitly leave the final decision to a human reviewer.
